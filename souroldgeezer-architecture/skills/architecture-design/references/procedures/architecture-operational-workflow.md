# Architecture Operational Workflow

Use after `SKILL.md` selects Build, Extract, Review, or Lookup.

- Pre-flight: identify package, notation/profile, kind, quality target, export need, runtime. Preserve ids, labels, policies, evidence.
- Runtime boundary: GitHub™ release bundles are imported upstream evidence. Resolve them with the skill's `references/scripts/dediren-release.sh` (path resolution in `self-check.md`); do not patch cached release files or future packaged bundles; report defects under `Dediren tool issues` per `architecture.md` §9.
- Agent usage: for source JSON authoring, command handoff, and repair loops, read the selected release guide from `dediren-release.sh --agent-guide` before loading schemas.
- Notation guard: ArchiMate and UML are supported profiles. Load the selected notation reference; stop on unsupported notation instead of degrading into an ArchiMate review. Add `archimate-oef` only for requested ArchiMate OEF export and `uml-xmi` only for requested UML XMI export.
- Build: update source/policies from architect intent; add actual views; validate, project, layout, validate-layout, render.
- Clean slate: start from the ArchiMate fixture for ArchiMate packages or the selected Dediren release bundle's matching UML fixture for UML packages, including sequence views. Authored files: `model.json`, `project.json`, `render-policy.json`, maintained `render-metadata.json`, optional `export-policy.json`. `generated/` metadata, layouts, SVG, optional OEF/XMI are reproducible output.
- Project recipe: `projection`, `metadata` to `generated/render-metadata/<view>.json`, `layout`, `render`. With the release-resolved Dediren runtime, set `plugins.generic-graph.semantic_profile`.
- Semantic guard: apply `architecture.md` §5 (interface/service semantics, component-interface ownership, Triggering for process sequencing); define the view concern, allowed element types, and relationship types. Ambiguous choices use `references/source-weighting.md`: source fact, candidates, chosen concept, weighted reason, confidence.
- Runtime semantics: apply `architecture.md` §9 (endpoint legality, `Node` naming, parallel per-view ELK layout, semantic profiles, notation-specific `source-valid`). relationship connectors and junctions are unsupported in dediren package source. Command templates live in `self-check.md`; do not duplicate them across task references.
- Extract: lift evidenced source/IaC/workflow/API/UI facts only; Business, Motivation, Strategy, Physical stay architect-owned.
- Groups: source-backed groups represent ownership, hosting, trust, environment, dependency, responsibility, or orchestration. Put them in `model.json` under `plugins.generic-graph.views[].groups`, not `project.json`. Layout-only groups are not ArchiMate Grouping elements; semantic-boundary needs `semantic_source_id`.
- Grouped layout: parallel per-view `layout --plugin elk-layout` is allowed with the release-resolved Dediren runtime; rerun parallel-only failures serially before `ARCH-L-1`. The grouped-layout fallback (rerun without groups, keep source-backed groups, report the regression plus both validation counts) is defined in `architecture.md` §9.
- Cross-notation links: UML may declare optional upward context to ArchiMate with `properties.uml.architecture_context` and `relationship: "elaborates"`. Verify referenced ids before claiming cross-notation readiness. Do not infer links from label similarity alone.
- Visual readiness: layout-valid is not visually clean; inspect density, fanout, routes, groups, labels, congestion, focus. For density/routing/framing problems, tune `layout_preferences` (`architecture.md` §9) and re-run `validate-layout` before reporting `ARCH-L-3` or splitting a view (§7); interactive/rich SVG render is an opt-in (§3).
- Review/Lookup: Review does not mutate by default and leads with findings. For implementation handoff sufficiency, load `implementation-readiness-review.md` and report an implementation-readiness review. Lookup cites package path/source ids.

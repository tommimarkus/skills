# Architecture Operational Workflow

Use after `SKILL.md` selects Build, Extract, Review, or Lookup.

- Pre-flight: identify package, notation/profile, kind, quality target, export need, runtime. Preserve ids, labels, policies, evidence.
- Runtime boundary: the plugin's Claude Code, Codex, and Copilot MCP adapters route to the current host-managed Dediren CLI; the plugin does not download or pin it. Pass an absolute `workspaceRoot` on every tool call and relative paths beneath it. Treat the external runtime as imported upstream evidence — do not patch the host installation; report defects under `Dediren tool issues` per `architecture.md` §9. If neither MCP nor the same external CLI lane can execute, cap at `source-valid` (`self-check.md` § Server availability).
- Agent usage: for source JSON authoring, command handoff, and repair loops, read the format contract through the `dediren_guide` tool (`{workspaceRoot: "/abs/project"}` for the index, then `{workspaceRoot: "/abs/project", topic: "source-json"}`) before loading schemas.
- Notation guard: ArchiMate and UML are supported profiles. Load the selected notation reference; stop on unsupported notation instead of degrading into an ArchiMate review. Add `archimate-oef` only for requested ArchiMate OEF export and `uml-xmi` only for requested UML XMI export.
- Build: update source/policies from architect intent; add actual views; validate (schema + semantic profile via `dediren_validate`), build the package through the MCP adapter (one `dediren_build` call with `workspaceRoot` and `package`, `self-check.md` § Building a package), then the `architecture.md` §9 accessible-name post-render step per rendered view. Close with the build readiness disclosure ([implementation-readiness-review.md](implementation-readiness-review.md) § Build Readiness Disclosure).
- Clean slate: start from the repo ArchiMate fixture for ArchiMate packages or a matching fixture exposed by the selected host runtime for UML packages, including sequence views. Authored files: `model.json`, `package.json`, `render-policy.json`, maintained `render-metadata.json`, optional `export-policy.json`. `generated/` metadata, layouts, SVG, optional OEF/XMI are reproducible output.
- Package recipe: projection, render-metadata (to `generated/render-metadata/<view>.json`), layout, render, and the export lanes all run inside one `dediren_build` call with the `package` argument, which writes every artifact to its declared path. Set `plugins.generic-graph.semantic_profile` in the source — it is the only place the notation is declared.
- Semantic guard: apply `architecture.md` §5 (interface/service semantics, component-interface ownership, Triggering for process sequencing); define the view concern, allowed element types, and relationship types. Ambiguous choices use `references/source-weighting.md`: source fact, candidates, chosen concept, weighted reason, confidence.
- Runtime semantics: apply `architecture.md` §9 (endpoint legality, `Node` naming, in-build layout, semantic profiles, notation-specific `source-valid`). relationship connectors and junctions are unsupported in dediren package source. The MCP tool call flow lives in `self-check.md`; do not duplicate it across task references.
- Extract: lift evidenced source/IaC/workflow/API/UI facts only; Business, Motivation, Strategy, Physical stay architect-owned.
- Groups: source-backed groups represent ownership, hosting, trust, environment, dependency, responsibility, or orchestration. Put them in `model.json` under `plugins.generic-graph.views[].groups`, not `package.json`. Layout-only groups are not ArchiMate Grouping elements; semantic-boundary needs `semantic_source_id`.
- Grouped layout: layout runs inside the `dediren_build` call; read the `package-build-result` per-view entries to isolate an `ARCH-L-1`. The grouped-layout fallback (rebuild without groups, keep source-backed groups, report the regression plus both validation counts) is defined in `architecture.md` §9.
- Cross-notation links: UML may declare optional upward context to ArchiMate with `properties.uml.architecture_context` and `relationship: "elaborates"`. Verify referenced ids before claiming cross-notation readiness. Do not infer links from label similarity alone.
- Visual readiness: layout-valid is not visually clean; inspect density, fanout, routes, groups, labels — including the `architecture.md` §7 label-to-own-edge distance check — congestion, focus, the `architecture.md` §9 accessible-name and visible-title markup (missing is `ARCH-R-2`), and for UML views the `architecture.md` §9 end-adornment coverage check (dropped authored adornments are `ARCH-R-2`). For density/routing/framing problems, tune `layout_preferences` (`architecture.md` §9) and rebuild the view before reporting `ARCH-L-3` or splitting a view (§7); renders are static SVG (§3) — verify the emitted SVG is script-free and report the verified mode per the `architecture.md` §9 render-mode check (a `<script>` or a footer misreport is `ARCH-R-5`).
- Review/Lookup: Review does not mutate by default and leads with findings. For implementation handoff sufficiency, load `implementation-readiness-review.md` and report an implementation-readiness review. Lookup cites package path/source ids.

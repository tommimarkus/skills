- The `dediren_guide` MCP tool serves the runtime's agent guide one topic at a time — the fast contract for source JSON authoring, command handoff, and repair loops.

- The pinned Dediren bundle's `dediren mcp` server exposes **seven** tools — the three above plus four read-only model-intelligence tools — and the skill drives all seven (the shipped tool surface is verified on the pinned bundle by `test_mcp_server_exposes_the_seven_tools_the_skill_drives`). Each new tool prints the standard `envelope.schema.v1` with its result document under `.data` (only `dediren_build` is unwrapped), and each is verified on the pinned 2026.07.28 bundle:
  - `dediren_diff` reports node / relationship / view `added` / `removed` / `changed` with field-level `{field, from, to}` changes and byte-deterministic output for identical inputs (`test_dediren_diff_reports_field_level_model_changes_deterministically`).
  - `dediren_query` answers the fixed kinds `dependents` (needs `--id`; `inbound` / `outbound` edges) / `orphans` (`relationship_orphans` / `view_orphans`) / `view-coverage` (data key `view_coverage`: per-view counts + `uncovered_node_ids`), and returns a `DEDIREN_COMMAND_INPUT_INVALID` usage envelope (exit 2) for an unknown `--kind` or a `dependents` call missing `--id` (`test_dediren_query_answers_the_three_fixed_kinds_and_rejects_bad_input`).
  - `dediren_verify` recomputes the model hash and classifies built artifacts `current` (ok, exit 0) / `stale` (`DEDIREN_ARTIFACT_STALE`, exit 2 — the CI drift gate) / `unstamped` (`DEDIREN_ARTIFACT_UNSTAMPED`, warning, exit 0) (`test_dediren_verify_gates_stale_build_artifacts_against_provenance`).
  - `dediren_status` indexes a workspace's source models (path + sha256) and stamped artifacts (path + status) as a read-only freshness index, not a gate (`test_dediren_status_indexes_workspace_models_and_artifacts`).
  - `dediren mcp --read-only` withholds the artifact-writing `dediren_build` and serves exactly the six read-only tools (`test_mcp_read_only_server_withholds_the_build_tool`).
- Every `dediren build` artifact carries a deterministic provenance stamp — an inert `<metadata id="dediren-provenance">` element in SVG (a leading `<!-- dediren-provenance … -->` comment in OEF/XMI) holding compact JSON with `model_sha256` (SHA-256 of the canonical model JSON), `view_id`, the lane policy hash, and `dediren_version`, never a timestamp — so identical inputs produce byte-identical artifacts and `dediren_verify` can decide freshness from them. The SVG stamp shape and byte-identical determinism are verified on the pinned 2026.07.28 bundle (`test_dediren_build_stamps_deterministic_provenance_into_svg`). Only `build` stamps: decomposed per-stage outputs are unstamped per the bundle's agent-usage contract (the render stage never sees the source model).
- `dediren build` with `--oef-policy` additionally writes a whole-model `model.oef.xml` at the out root, and `--xmi-policy` on a UML model a whole-model `model.uml.xml`, each listed in the build-result `model_artifacts[]`; both interchange legs are verified on the pinned 2026.07.28 bundle against the `basic` (OEF) and `mixed` (XMI) fixtures (`test_dediren_build_writes_whole_model_interchange_for_oef_and_xmi`). This whole-model export is distinct from the per-view `oef.xml` / `xmi.xml` the export lanes also write.
- Per-view `uml-xmi` export is verified for non-class view kinds, not only `uml-class`: on the pinned 2026.07.28 bundle a `uml-sequence` view emits one `uml:Interaction` with nested `<lifeline>` / `<message>` children and `uml:MessageOccurrenceSpecification` fragments (plus `uml:CombinedFragment` / `uml:InteractionConstraint` / `uml:OpaqueExpression` for combined-fragment sources), and a `uml-deployment` view emits `Device` / `ExecutionEnvironment` / `Node` / `Artifact` / `DeploymentSpecification` / `Component` classifiers with `Deployment` / `Manifestation` / `CommunicationPath` relationships — each view emitted whole with no `DEDIREN_XMI_ELEMENTS_OMITTED` / `DEDIREN_XMI_RELATIONSHIPS_OMITTED` diagnostic (`test_release_uml_sequence_fragments_full_pipeline`, `test_release_uml_deployment_worked_example_xmi_full_pipeline`).

- Source-backed groups belong in `model.json` under `plugins.generic-graph.views[].groups`; simple linear flows stay ungrouped unless responsibility, trust, participant, or orchestration changes reading.
- The tested Dediren runtime enforces ArchiMate® 3.2 relationship endpoint legality, expects `Node`, not `TechnologyNode`, reports close parallel route channels, supports `plugins.generic-graph.semantic_profile`, and runs projection, layout, layout validation, and rendering inside each `dediren_build` call.
- The layout-request `layout_preferences` object (`mode` / `direction` / `density` / `wrapping` / `routing`, plus the ELK Layered tuning knobs, per-node `layer_constraint` / `partition` placement hints, and per-edge `priority` routing hints in `architecture.md` §9) tunes ELK placement/routing as presentation only — a utilization lever, not a new finding. Dediren retired the render-policy `interactive` field at render-policy schema v3 (2026.07.18); renders are static SVG only.
- ArchiMate and UML are supported `generic-graph` semantic profiles for `architecture-design`; UML uses `dediren_validate {workspaceRoot, profile: "uml"}`, local Dediren view families `uml-class` / `uml-data` / `uml-activity` / `uml-sequence` / `uml-state-machine` / `uml-use-case` / `uml-component` / `uml-deployment`, optional `uml-xmi` export, and `properties.uml` for attributes, operations, multiplicities, guards, partitions, optional architecture context, and sequence detail. `uml-data` is a Dediren-local classifier-structure view, not a UML Annex A diagram kind.
- Dediren UML sequence views use `uml-sequence` with `Interaction`, `Lifeline`, and `Message` source elements; message ordering lives in `properties.uml.sequence` and message category in `message_sort`.
- The `dediren_guide` MCP tool serves the runtime's agent guide one topic at a time — the fast contract for source JSON authoring, command handoff, and repair loops.
- Dediren 2026.07.17 added a `dediren mcp` stdio server exposing `dediren_validate` / `dediren_build` / `dediren_guide`. The plugin bundles the Claude Code, Codex, and Copilot adapters plus a protocol/workspace router and a runtime resolver; it executes an explicit `DEDIREN_COMMAND`, its own managed install under the host's plugin data directory, a floor-meeting `dediren` on `PATH`, or the newest executable already present in the former verified release cache, and otherwise provisions the pinned checksum-verified release (2026.08.4, floor 2026.07.28) on first use. Java stays host-managed and is never downloaded. It discovers the resolved installation's live tools and adds required absolute `workspaceRoot` routing. The router bounds upstream waits, closes catalog-only and shutdown children, replaces known-dead workspace processes for the next call, and never auto-retries an uncertain tool call. Workspace children use their root cwd and catalog discovery uses the resolved launcher directory. Backend stderr is mirrored, while errors retain only a 4 KiB head plus 12 KiB tail with command, cwd, and exit context; stdout stays JSON-RPC only. Deleted inherited-cwd and oversized-stderr regressions cover cached and cold discovery. `dediren_build` takes a `package` argument (plus optional `no_export`), mutually exclusive with the single-model arguments, and writes every declared artifact straight to its `package.json` path; `dediren_validate` takes an optional `profile`. The fixture compatibility baseline remains 2026.08.3 and is verified end-to-end on the adopted 2026.08.4 runtime.
- Dediren 2026.08.4 adds inline Mermaid/DOT import plus negotiated SVG/PNG MCP response attachments and replaces external export-schema fetching with a bounded Java HTTP client. The adapter already derives allowed arguments from the live tool schema and forwards result content unchanged, so no host-specific fork is needed; the live candidate test proves JSON-first inline import followed by an `image/svg+xml` content item, while architecture-design's trigger boundary still excludes Mermaid/DOT artifacts the user wants to keep in those formats. The candidate suite proved both export lanes when schema HTTP was available; network-denied hosts retain the existing offline schema overrides.
- The skill requires **seven** Dediren tools — the three above plus four read-only model-intelligence tools — while the router preserves any newer tools reported by the installed release. The required baseline is verified by `test_mcp_server_exposes_the_seven_tools_the_skill_drives`; each intelligence tool prints the standard `envelope.schema.v1` with its result document under `.data` (only `dediren_build` is unwrapped), verified on adopted Dediren 2026.08.4:
  - `dediren_diff` reports node / relationship / view `added` / `removed` / `changed` with field-level `{field, from, to}` changes and byte-deterministic output for identical inputs (`test_dediren_diff_reports_field_level_model_changes_deterministically`).
  - `dediren_query` answers the fixed kinds `dependents` (needs `--id`; `inbound` / `outbound` edges) / `orphans` (`relationship_orphans` / `view_orphans`) / `view-coverage` (data key `view_coverage`: per-view counts + `uncovered_node_ids`), and returns a `DEDIREN_COMMAND_INPUT_INVALID` usage envelope (exit 2) for an unknown `--kind` or a `dependents` call missing `--id` (`test_dediren_query_answers_the_three_fixed_kinds_and_rejects_bad_input`).
  - `dediren_verify` recomputes the model hash and classifies built artifacts `current` (ok, exit 0) / `stale` (`DEDIREN_ARTIFACT_STALE`, exit 2 — the CI drift gate) / `unstamped` (`DEDIREN_ARTIFACT_UNSTAMPED`, warning, exit 0) (`test_dediren_verify_gates_stale_build_artifacts_against_provenance`).
  - `dediren_status` indexes a workspace's source models (path + sha256) and stamped artifacts (path + status) as a read-only freshness index, not a gate (`test_dediren_status_indexes_workspace_models_and_artifacts`).
  - `dediren mcp --read-only` withholds the artifact-writing `dediren_build` and serves exactly the six read-only tools (`test_mcp_read_only_server_withholds_the_build_tool`).
- Every `dediren build` artifact carries a deterministic provenance stamp — an inert `<metadata id="dediren-provenance">` element in SVG (a leading `<!-- dediren-provenance … -->` comment in OEF/XMI) holding compact JSON with `model_sha256` (SHA-256 of the canonical model JSON), `view_id`, the lane policy hash, and `dediren_version`, never a timestamp — so identical inputs produce byte-identical artifacts and `dediren_verify` can decide freshness from them. The SVG stamp shape and byte-identical determinism are verified on the adopted 2026.08.4 bundle (`test_dediren_build_stamps_deterministic_provenance_into_svg`). Only `build` stamps: decomposed per-stage outputs are unstamped per the bundle's agent-usage contract (the render stage never sees the source model).
- `dediren build` with `--oef-policy` additionally writes a whole-model `model.oef.xml` at the out root, and `--xmi-policy` on a UML model a whole-model `model.uml.xml`, each listed in the build-result `model_artifacts[]`; both interchange legs are verified on the adopted 2026.08.4 bundle against the `basic` (OEF) and `mixed` (XMI) fixtures (`test_dediren_build_writes_whole_model_interchange_for_oef_and_xmi`). This whole-model export is distinct from the per-view `oef.xml` / `xmi.xml` the export lanes also write.
- Per-view `uml-xmi` export is verified for advertised kinds from the adopted 2026.08.4 runtime's direct `export-result.schema.v2` `.data.assurance` object. Its exhaustive `kind_taxonomy` distinguishes the seven standard UML view kinds from the local `uml-data` classifier view and keeps model aggregate plus provisional UMLDI support class/data-only; `artifact_scope` names the selected view kinds; `coverage` partitions represented, omitted, and in-view-unrepresented element/relationship counts by type; and `validation_evidence` reports the exact validation level and evidence. The sequence full-pipeline regression independently verifies that machine contract against the provisioned release. Diagnostics remain complementary detail, but direct-result coverage and validation claims come from assurance rather than inferred message prose. The native package-build-result does not surface assurance; the default package-build path therefore retains artifact/source comparison plus export diagnostics and discloses that evidence limit rather than fabricating the direct result. Map `xmi-envelope-only`, `uml-content-schema-validated`, or `importer-validated` to exactly one human disclosure: `XMI envelope only`, `UML-content schema`, or `importer validated`; never call envelope-only XMI conformant UML abstract syntax. [Dediren issue #71](https://github.com/tommimarkus/dediren/issues/71) records the provenance of this assurance contract.

- Dediren runtimes before the accessible-name fix emitted SVG with no accessible-name markup (`role`, `aria-*`, `<title>`, `<desc>`), failing WCAG 2.2 SC 1.1.1 (<https://www.w3.org/TR/WCAG22/#non-text-content>); the gap went upstream, not into local bundle patches, and current Dediren emits `role="img"` plus a `<title>` and optional `<desc>`. Dediren 2026.07.28 relocated that text to each view's own `presentation` title/question, making the name per view rather than per policy (a policy-level `accessibility` block outranks it and is therefore not authored — verified on adopted Dediren 2026.08.4 across all three fixture views). What stays unrendered is the *visible* per-view title, which upstream declined as caller-side chrome on SC 1.1.1 double-labelling grounds, so the §9 post-render step (`references/scripts/svg-accessible-name.py`) exists for that band. Because the name is now the runtime's, the step no longer synthesises one: `2026.07.28` remains the declared support floor, checked against the external CLI rather than enforced by a plugin resolver, and an artifact reaching the step without an accessible name is refused with exit 4 rather than banded.

- `package.schema.v1` is closed (`additionalProperties: false`) and has no per-model `profile`, so the notation rides only on each `model.json`'s `plugins.generic-graph.semantic_profile`. Dediren 2026.07.29 (upstream dediren#66) added a package-level `presentation` of exactly `{ lang?, dir? }`: the runtime pushes the pair into each view's render policy (an explicit per-view value overrides it), echoes it in `package-build-result`, and writes it onto every SVG root as `xml:lang` / `direction`. Neither key has a default, so a package that declares nothing renders byte-for-byte as it did before. Package-level `feature` was declined upstream as caller-side page chrome, and the canonical `docs/architecture/<feature>.dediren/` directory name supplies it losslessly, so the skill's former `project.json` sidecar (`souroldgeezer.architecture.dediren.presentation.v1`) is retired and `package.json` is the only authored manifest. Verified on the Dediren 2026.08.3 compatibility baseline under adopted Dediren 2026.08.4 against the `rendered` fixture: package `presentation` echoed in the build result and both attributes present on all three SVG roots, surviving the §9 accessible-name step byte-identically on rerun.
- Per-view `presentation.title` / `question` reach the render lane as that view's native SVG `<title>` / `<desc>`, but a render policy's own `accessibility.title` / `.description` overrides them — so a policy shared by several views stamps one view's text onto all of them (observed on the `rendered` fixture, where a shared `render-policy-uml.json` labelled both UML views "Mixed - Domain Class View"). Packages therefore leave `accessibility` out of shared render policies and let the per-view presentation supply the accessible name; verified on the adopted 2026.08.4 bundle, where removing the block restored all three fixture views' correct per-view names.

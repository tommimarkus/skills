# .NET/C# IP Hygiene Extension

Loaded when reviewed files include `*.cs`, `*.csproj`, `*.sln`, or another
.NET project/solution file, per
[SKILL.md § Scope And Load Map](../SKILL.md) and
[extension-authoring.md § Load Order](../references/procedures/extension-authoring.md).
Applies [source-code.md](../references/source-code.md)'s four classes and
notice-survival procedure; does not restate them.

## Detection Signals

`*.cs` source files; `*.csproj`, `*.sln`, and `Directory.Build.props` project
files; a `*.nuspec` file when a NuGet package is packed from the project.

## Comment And Doc-Comment Syntax

Line comments (`//`) and block comments (`/* */`). Doc comments use the
triple-slash XML form (`/// <summary>...</summary>`), with `<remarks>`,
`<param>`, and `<returns>` as the prose-bearing elements. `<inheritdoc/>`
copies the doc comment from a base member or implemented interface member
rather than restating it — a member using it carries no doc-comment prose of
its own, so `source-code.md`'s "Copied doc-comment prose" class does not apply
to it directly; check the member it inherits from instead.

## Header Placement And Ordering

A licence header or `SPDX-License-Identifier` line sits at the very top of
the file, before any `using` directives and before the `namespace`
declaration.

## Ecosystem Licence Metadata

A packed project declares its licence through one of two mutually exclusive
`.csproj`/`.nuspec` properties: `PackageLicenseExpression` (an SPDX licence
expression string) or `PackageLicenseFile` (a path to a licence file included
in the package). This is package-level metadata for the project's own output;
it says nothing about the licence of third-party material embedded or
referenced inside that project, which stays subject to `IP-LIC-4` layering.

## Vendoring Conventions

No NuGet-standard vendoring directory exists; restored package assemblies
live under `obj`/`packages` build output and are managed dependencies, not
vendored copies, so they are not themselves reviewed for per-file notices.
When third-party source is copied directly into the tree, look for a
project-chosen directory (commonly named `ThirdParty` or `vendor`) and
confirm it retains the source's own licence file.

## Generated-Code Banners

Tooling-generated `.cs` files commonly open with an `<auto-generated>` XML
comment block stating the file was produced by a tool and should not be
edited by hand; static-analysis tooling recognizes this exact block to
exclude the file from style rules. Treat it as `IP-SRC-5` provenance evidence
for the generator/input/output split, not as a licence determination.

## Notice-Survival Mechanics

.NET does not minify source the way JavaScript does; the load-bearing fact
here is different. Compilation to IL discards comments unconditionally — a
source-level licence header or doc comment never reaches the compiled
assembly regardless of build configuration, so a notice obligation that must
survive to a binary distribution cannot rely on any in-source mechanism at
all. The ecosystem convention for that case is a `ThirdPartyNotices.txt` file
shipped alongside the distributed binaries, aggregating the required notices
for embedded or statically linked third-party material, plus the packed
`PackageLicenseExpression`/`PackageLicenseFile` metadata above for the
project's own declared licence. Decompiler-sourced code is a distinct
acquisition path under core `IP-SRC-1`: code recovered from a compiled
assembly via a decompiler (ILSpy, dotPeek, and similar) is its own provenance
category, distinct from source
obtained directly from the original project — it carries no original
comments or notices (already lost at compilation, per above) and raises a
separate terms question about whether decompiling that assembly was itself
permitted; treat decompiler-sourced material as an unresolved-terms evidence
gap per [SKILL.md § Counsel Escalation And Stops](../SKILL.md), not as
clearance to use it because the original licence appears permissive.

## Mark Surfaces

`AssemblyInfo.cs` attributes (`AssemblyProduct`, `AssemblyCompany`,
`AssemblyCopyright`), the NuGet `PackageId` property, and string literals used
as HTTP `User-Agent` values are the surfaces most likely to carry a
third-party mark in this ecosystem; apply
`IP-MARK-1`/`IP-MARK-2`/`IP-MARK-4` per
[source-code.md § Marks In Code](../references/source-code.md).

## Criteria

This pack carves out no core criterion and adds none; it applies the core
`IP-LIC-*`, `IP-SRC-*`, `IP-COPY-*`, and `IP-MARK-*` criteria via the facts
above, including `IP-SRC-1` for decompiler-sourced provenance. No
`dotnet.IP-*` numbered criterion is defined.

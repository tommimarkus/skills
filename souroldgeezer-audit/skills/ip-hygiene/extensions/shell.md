# Shell IP Hygiene Extension

Load for `*.sh`, `*.bash`, `*.zsh`, or an extensionless file whose first
line is a shell shebang. Adds the language-specific facts
[source-code.md](../references/source-code.md) defers to each language;
does not restate its four classes, notice-survival list, or
generated-material split. Several sections below state that the usual
mechanism does not exist for shell — that absence is itself the
language-specific fact and is recorded, not skipped.

## Detection signals

`*.sh`, `*.bash`, `*.zsh`, and any extensionless file whose first line
matches a shebang for `sh`, `bash`, `zsh`, `dash`, or `ash` (e.g.
`#!/bin/sh`, `#!/usr/bin/env bash`).

## Comment and doc-comment syntax

One comment form, `#` to end of line, no block-comment delimiter. No
standardized doc-comment convention comparable to a docstring or JSDoc —
tools such as `shdoc` read a project-chosen `#`-comment convention, not a
language-level one. "Copied doc-comment prose" therefore has no dedicated
surface beyond ordinary `#` comments; treat a `#`-comment block preceding a
function as a candidate the same as any other comment, with no separate
doc-comment marker to search for.

## Header placement and ordering

A shebang must remain the file's absolute first line to be honored by the
kernel's `execve` loader — a licence header or `SPDX-License-Identifier`
line can never precede it, unlike languages where the header is first. The
header instead sits immediately after the shebang, before `set -e`/`set -u`
option lines or the first executable statement. A `# shellcheck
disable=<code>` or `# shellcheck source=<path>` directive is typically
grouped with or right after the header; it only takes effect for the
statement/file it is attached to, so its presence adjacent to a header
hints at the header's boundary without being part of it.

## Ecosystem licence metadata

Shell has no package ecosystem and no manifest field for licence — no
equivalent of a `pyproject.toml` `license` key or `package.json` `license`
field. A distro packaging layer (`debian/copyright` for a `dpkg` package, an
RPM spec `License:` tag) may declare licence for a *packaged* script, but
that metadata lives outside the script's own repository and is frequently
absent in source form. File-level notices are therefore the only evidence
this pack can rely on; their absence is not offset by an ecosystem layer the
way it might be elsewhere.

## Vendoring conventions

No vendoring directory convention analogous to `vendor/`. The dominant
provenance risk is instead the `source` builtin (or its `.` synonym), which
executes another file's content inline at run time with no copy step and no
manifest anywhere recording that file's origin — a sourced file can carry
third-party code into execution with zero filesystem evidence of vendoring.
When a `source`/`.` target resolves outside the project (a system path, a
downloaded artifact), treat that as an unresolved-provenance evidence gap
the same way `source-code.md` treats an unresolved-licence attribution
comment, per
[SKILL.md § Counsel Escalation And Stops](../SKILL.md).

## Generated-code banners

GNU Autoconf's generated `configure` script opens with a comment naming the
`autoconf` version and the `configure.ac`/`configure.in` input (to the
effect of "Generated from configure.ac by GNU Autoconf") — Autoconf is the
generator, `configure.ac` the input, `configure` the output for the
`IP-SRC-5` split. Shell completion scripts emitted by a CLI's own generator
(e.g. `argcomplete`, a `--generate-completion` flag, or a build tool's
`bash`/`zsh` completion output) commonly carry a leading `# Generated by
<tool>` or `# DO NOT EDIT` comment naming the generator and the CLI's
argument definitions as input.

## Notice-survival mechanics

No standard minifier or bundler analogous to a JavaScript build pipeline
exists for shell, so the minification notice-loss path does not apply. What
does strip comments is packaging into a single-file distributable — a
`makeself` self-extracting archive, or a project's own `cat`-based build
step concatenating several scripts into one file. None of those tools has a
standard "preserve comment" pragma comparable to a JS minifier's `/*! ... */`
convention, so concatenation is a real, unmitigated notice-loss path here:
confirm manually that per-file headers survived into the output.

## Mark surfaces

A `--version`/banner string printed by the script and a `User-Agent` string
literal passed to `curl -A`/`--user-agent` or `wget --user-agent` are the
two recurring mark surfaces (`IP-MARK-1`, `IP-MARK-2`). Shell has no
package-name manifest field to double as a mark surface, since it has no
package manifest at all (see "Ecosystem licence metadata").

## Criteria

Carves out no core criterion and adds none; applies the core `IP-LIC-*`,
`IP-SRC-*`, `IP-COPY-*`, `IP-MARK-*` criteria via the facts above. No
`shell.IP-*` numbered criterion is defined.

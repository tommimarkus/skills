# Python IP Hygiene Extension

Load for `*.py`, `*.pyi`, or a Python package manifest. Adds the
language-specific facts [source-code.md](../references/source-code.md)
defers to each language; does not restate its four classes, notice-survival
list, or generated-material split.

## Detection signals

`*.py`, `*.pyi`; `pyproject.toml`, `setup.py`, `setup.cfg`,
`requirements*.txt`, or `Pipfile` in the tree; a `site-packages/` or
`.venv/`/`venv/` directory when its contents are in scope.

## Comment and doc-comment syntax

Line comments use `#`; no block-comment delimiter, only consecutive `#`
lines. The doc-comment convention is the docstring: a string literal as the
first statement in a module, class, or function body, usually triple-quoted
(`"""..."""`/`'''...'''`). "Copied doc-comment prose" applies to docstring
bodies, not `#` comments, which more often carry the notices/attribution
classes instead.

## Header placement and ordering

A licence header or `SPDX-License-Identifier` line, as a leading `#` block,
must precede the module docstring when both are present — the docstring as
*first* statement is what makes it `__doc__` and doc-tooling-readable, so a
header placed after it is easy to mistake for the docstring by tools that
scan only the first statement. Two mechanisms interleave with a leading
header and are not the header itself: a `# -*- coding: ... -*-` (PEP 263)
declaration, which must sit on line one or two to take effect, and
`from __future__ import ...`, which must precede other executable statements
but may follow the docstring and header. Check both sides of these before
concluding a header is absent.

## Ecosystem licence metadata

`pyproject.toml` declares licence under `[project] license` (historically
free text, and under PEP 639 a `license-files` glob to the bundled licence
file(s)). The older `setup.py`/`setup.cfg` convention passes `license=` to
`setup()`, often paired with a `License ::` Trove classifier. None of these
is itself the notice: a manifest `license` value states the ecosystem's
belief about the whole distribution and does not confirm any file's header
(`IP-LIC-4`).

## Vendoring conventions

Python vendors third-party packages either by committing a full copy under a
project-chosen `vendor/`/`_vendor/` directory (`pip`'s own pattern, no single
canonical name) or by shipping a pinned wheel/sdist in the repository. A
`site-packages/` tree or installed `.venv/`/`venv/` directory is *installed*
third-party code, not vendored code, and is ordinarily excluded from a
distributed source tree; a commit of either into version control is a signal
worth checking, since it carries full upstream licence/notice obligations
into the repository regardless of intent.

## Generated-code banners

`protoc`/`grpcio`-generated modules open with a `# -*- coding: utf-8 -*-`
line and a comment naming the source `.proto` file and generator (to the
effect of "generated by the protocol buffer compiler, do not edit"). Alembic
migration scripts open with a docstring header giving `Revision ID`,
`Revises`, `Create Date` — that identifies the migration but is not a
"DO NOT EDIT" banner, since migrations are meant to be hand-edited after
generation. Apply the generator/input/output split (`IP-SRC-5`) to whichever
banner is present.

## Notice-survival mechanics

Python source shipped as wheel/sdist is not minified by a standard toolchain
step the way JavaScript is; the default packaging path copies `.py` files
(or compiles to `.pyc`) without stripping comments, so a header or docstring
generally survives intact. What does strip it instead is a bytecode-only
distribution (`.pyc`/`.pyo` without source) or an explicit
minifier/obfuscator run as a separate build step; where a project uses one,
confirm that tool's own comment-preservation option, since no
standard-library or PEP mechanism guarantees one.

## Mark surfaces

`[project] name` in `pyproject.toml` (or `setup()`'s `name=`) is the
package's PyPI identity and the most common spot for a third-party mark to
appear verbatim. A `User-Agent` string on an HTTP client (`requests`,
`httpx`, `urllib3`) and CLI `--version`/banner strings are the other two
recurring mark surfaces (`IP-MARK-1`, `IP-MARK-2`).

## Criteria

Carves out no core criterion and adds none; applies the core `IP-LIC-*`,
`IP-SRC-*`, `IP-COPY-*`, `IP-MARK-*` criteria via the facts above. No
`python.IP-*` numbered criterion is defined.
